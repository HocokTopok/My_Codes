# Result

*References*: [rust/result](https://doc.rust-lang.org/std/result/), [std::expected](https://en.cppreference.com/w/cpp/utility/expected.html)

## Условие

В этой задаче вам нужно реализовать `Result` - иммутабельный шаблонный класс, аналог std::expected или Result из Rust,
предоставляющий [монадный](https://en.wikipedia.org/wiki/Monad_(functional_programming)) интерфейс для
обработки ошибок.

Использование std::variant, std::optional или std::expected запрещено.

Синопсис:

```c++
template <typename Ok, typename Err>
class Result;
```

### Комбинаторы

Вы должны предоставить следующие комбинаторы. В терминах функционального программирования их сигнатуры выглядят так:

```c++
AndThen: Result<T, E> -> (T -> Result<U, E>) -> Result<U, E>
OrElse: Result<T, E> -> (E -> Result<T, Y>) -> Result<T, Y>
```

Эти операции формируют непрерывный пайплайн обработки данных и сохраняют «противоположный» тип неизменным (для упрощения
использования в реалиях C++ допускается неявное изменение вплоть до std::convertible_to). Для понимания control flow
пайплайна примите таблицу как ориентир:

| method  | self   | function input | function result | output |
|---------|--------|----------------|-----------------|--------|
| AndThen | Err(e) | (ignored)      | (ignored)       | Err(e) |
| AndThen | Ok(x)  | x              | Err(d)          | Err(d) |
| AndThen | Ok(x)  | x              | Ok(y)           | Ok(y)  |
| OrElse  | Err(e) | e              | Err(d)          | Err(d) |
| OrElse  | Err(e) | e              | Ok(y)           | Ok(y)  |
| OrElse  | Ok(x)  | (ignored)      | (ignored)       | Ok(x)  |

Таким образом, пайплайн проходит сквозь методы, не обрабатывающие соответствующие значения, не вычисляя их.

---

Следующим видом комбинаторов являются мапперы - методы, преобразующие соответствующий тип:

```c++
Map: Result<T, E> -> (T -> U) -> Result<U, E>
MapError: Result<T, E> -> (E -> Y) -> Result<T, Y>
```

Пайплайн аналогично проходит сквозь методы, не обрабатывающие соответствующие значения.

---
Замечание: функторы, принимаемые комбинаторами, всегда принимают аргументы по rvalue.

### Access methods

Для получения значения/ошибки из `Result` от вас требуется реализовать следующие методы:

```c++
T&& Value() &&;
const T& Value() & const;
T ValueOr(?) ?;

E&& Error() &&;
const E& Error() & const;
E ErrorOr(?) ?;
```

и метод проверки текущего значения:

```c++
bool HasValue() const;
```

### Создание

У класса нет публичных конструкторов кроме Copy и Move, единственный способ достать класс - через внешние методы:

```c++
result::Value(...);
result::Error(...);
```

### Инвариант структуры

Для корректной реализации необходимо обеспечить следующие свойства:

1) Иммутабельность: Данные в классе невозможно изменить после инициализации. Любая монадная трансформация порождает
   новый объект.
2) Взаимоисключаемость: Экземпляр всегда находится строго в одном из двух состояний. Хранить значение и ошибку
   одновременно не имеет смысла.
